# Prospective study design

## Purpose

This family owns P2's identification-to-operation research, public
evaluation-system audits, prospective evaluator-validity designs, and the
source/lifecycle evidence needed to decide whether those designs are
applicable. These records constrain future studies; they do not expand P1's
bounded corpus claims.

Detailed questions and legacy dispositions are indexed in
`../HYPOTHESES.md`. Protocols, machine results, source records, independent
challenges, and tests remain canonical in this directory.

## Inputs and provenance

The family uses fixed public papers, project pages, repository revisions,
release metadata, and outcome-stripped public records identified in each
protocol. Repository-wide external findings remain canonical in
`../../../FINDINGS.md`. Release-critical sources must be pinned to revisions or
content hashes; current webpages and repository heads are source states, not
stable scientific identities.

H211's three metadata-only Git repository snapshots are retained under
`sources/h211-repositories/` at the revisions and remote identities recorded by
its protocol and result. They are partial-clone object stores used by the
offline producer and challenge paths, not complete vendored working trees.

P2's E2 preprocessing dependency is owned by
`../oscar-input-reconstruction/` and bounded by that family's staged
validation. Public refreshes may require network access. Outcome-sealed and
source-only boundaries declared by individual protocols remain controlling.

## Reproduction

From the project root:

```bash
make p2-manuscript-verify
.venv/bin/python -m pytest research/prospective-study-design -q
make p2-pdf
/usr/bin/python3 research/prospective-study-design/build_sim2real_evaluation_record_v1_r112_constraint_schema.py
/usr/bin/python3 research/prospective-study-design/build_sim2real_evaluation_record_v1_r112_fixture.py
/usr/bin/python3 research/prospective-study-design/challenge_sim2real_evaluation_record_v1_r112_classifier.py
make evaluation-record-r112-public-projections
make source-native-record-preflight
make p2-review-guide-candidate-binding
```

`p2-manuscript-verify` executes every current producer and independent
challenge dependency selected for the P2 manuscript. Each retained protocol
documents its narrower command, source state, expected output, and stop rule.
Family modules remain independently runnable so one failed component can be
diagnosed without rerunning the whole program.

H250 is synthetic and outcome-free. It propagates jointly valid edge
intervals to target bounds, winner certificates, and a minimax action; it does
not define an empirical sampling unit or authorize opening PhAIL outcomes.

## Dependencies and access

The family references current project evidence and the repository-wide
findings ledger. External refreshes require public access and must be treated
as new source states. Future empirical work needs a version-bound,
source-native assignment and lifecycle record; additional timestamp or proxy
subdivision cannot substitute for that missing mechanism.
